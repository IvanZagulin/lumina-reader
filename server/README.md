# Lumina Social — бэкенд

Маленький сервер, чтобы ты и друзья видели, кто что читает: общий круг,
оценки книг и прогресс. Только метаданные (название, автор, оценка, сколько
прочитано) — **файлы книг сюда не передаются**.

Отдельный от приложения проект: свой Gradle, свой Docker. Мобильную сборку не
трогает, деплоится сам по себе.

## Что это делает

- один общий круг: у кого есть приглашение — все видят всех;
- приглашения одноразовые, их создаёшь ты админ-токеном;
- приложение присылает свою «полку» (что читаю, оценка, прогресс) и забирает
  полки остальных;
- делится только то, что пользователь сам включил в приложении — сервер хранит
  ровно присланное.

## Деплой на свой сервер

На сервере нужен Docker с плагином compose.

1. Скопируй папку и настрой секреты:

   ```bash
   scp -r server ivanz@89.23.118.245:~/lumina-social
   ssh ivanz@89.23.118.245
   cd lumina-social
   cp .env.example .env
   nano .env            # впиши ADMIN_TOKEN (openssl rand -base64 32) и пароль БД
   ```

2. Подними:

   ```bash
   docker compose up -d --build
   ```

   Поднимутся Postgres и сервер. Сервер слушает **127.0.0.1:8080** — наружу
   напрямую не торчит специально (см. «Безопасность»).

3. Проверь, что живой (с сервера):

   ```bash
   curl -s -X POST localhost:8080/api/invites -H "X-Admin-Token: <твой ADMIN_TOKEN>"
   # -> {"code":"xxxxxxxx"}
   ```

Логи и управление:

```bash
docker compose logs -f server
docker compose restart server
docker compose down          # остановить (данные в томе lumina-db сохранятся)
```

## Как позвать друга

1. Создай приглашение:

   ```bash
   curl -s -X POST https://<твой-домен>/api/invites -H "X-Admin-Token: <ADMIN_TOKEN>"
   ```

2. Передай другу полученный `code`. В приложении он введёт его один раз —
   приложение обменяет код на токен и дальше ходит с ним само.

## API

| Метод | Путь | Кто | Зачем |
|---|---|---|---|
| POST | `/api/invites` | админ-токен в `X-Admin-Token` | создать одноразовое приглашение |
| POST | `/api/redeem` | — | обменять код на аккаунт и токен |
| GET | `/api/me` | `Bearer` | проверить токен / кто я |
| PUT | `/api/me/books` | `Bearer` | заменить свою полку целиком |
| GET | `/api/circle` | `Bearer` | полки всех остальных — лента |

## Безопасность — прочитай

- **Поставь TLS.** Токены ходят в заголовке `Authorization`; без HTTPS их видно
  в сети. Самое простое — Caddy перед сервером (сам получит сертификат):

  ```
  # /etc/caddy/Caddyfile
  social.твой-домен.рф {
      reverse_proxy 127.0.0.1:8080
  }
  ```

  Тогда приложение ходит на `https://social.твой-домен.рф`, а 8080 остаётся на
  localhost.
- `ADMIN_TOKEN` — длинный и случайный (`openssl rand -base64 32`). Им создаются
  приглашения; утечёт — любой наделает инвайтов.
- `.env` в git не попадает (см. `.gitignore`), не коммить его.
- Это персональные данные (что человек читает). Для себя и пары друзей — норм;
  публичным сервисом это не делает, модерации и удаления по требованию здесь нет.
